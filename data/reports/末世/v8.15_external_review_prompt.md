## 一、实验背景

在v8.14审视中，三方AI一致认为"run-to-run方差0.955 > 改善量0.489"是否决Reference-Based Scoring的核心依据(Q1)。本次实验旨在量化这个方差的真实大小。

### v8.14审视中的关键数据

| 数据 | 来源 | 说明 |
|------|------|------|
| 存档Bias=+1.859 | v8.12时期的T1评分 | 未知temperature |
| 新鲜Bias=+0.904 | v8.14脚本重跑 | **temperature=0.1** (llm_score_rubric默认值) |
| 参考Bias=+0.415 | v8.14 reference scoring | **temperature=0.0** (llm_score_reference_based默认值) |
| 方差=0.955 | 存档vs新鲜的Bias差 | 被三方AI视为"噪声" |

**⚠️ v8.14的不公平对比**: Reference评分用temperature=0.0，Absolute评分用temperature=0.1(默认值)。两者的"改善"部分来自温度差异，而非reference方法本身。

## 二、实验设计

### 脚本

`scripts/v815_run_to_run_variance.py`

### 方法

1. 加载47章golden数据(human_golden_merged.csv)
2. 对每章调用 `llm_score_rubric(text, ch_num, temperature=0.0)` — **明确指定temperature=0.0**
3. 重复3次独立运行
4. 每次计算MAE/Bias/Pearson r
5. 报告均值±标准差

### 代码关键行

```python
# 第125行: 明确传入temperature=0.0
result = llm_score_rubric(text, ch_num, temperature=0.0)
```

`llm_score_rubric`函数签名(第394行):
```python
def llm_score_rubric(chapter_text, ch_num, conn=None, prev_context="", sub_genre="", temperature=0.1):
```
默认temperature=0.1，本次实验明确覆盖为0.0。

### 与v8.14的区别

| 维度 | v8.14"新鲜绝对" | v8.15本次实验 |
|------|----------------|-------------|
| 函数 | `llm_score_rubric()` | 同 |
| temperature | 0.1 (默认) | **0.0 (显式)** |
| prev_context | 有(前章末尾200字) | **无**(简化) |
| 文本截断 | llm_score_rubric内部1200字 | 同(外部也截1200) |
| 重复次数 | 1次 | **3次** |

| 文本截断 | ✅ | 外部截1200+内部截1200=无害(同长度) |

### 4.2 结果可信度

| 方面 | 可信度 | 依据 |
|------|--------|------|
| 3次相同(std=0) | ⭐⭐⭐⭐⭐(99%) | temperature=0.0=greedy decoding，数学上必然确定 |
| Bias从+0.904→-0.181 | ⭐⭐⭐⭐(80%) | 温度影响采样分布，高分token概率被放大时temp>0会偏向高分 |
| r=0.494是历史最佳 | ⭐⭐⭐⭐(80%) | 减少噪声必然提升相关性 |
| v8.14对比不公平 | ⭐⭐⭐⭐⭐(95%) | 代码可直接验证：abs用0.1，ref用0.0 |

### 4.3 潜在问题

1. **prev_context缺失**: 本实验没传前章上下文。生产代码会传。如果prev_context影响评分，则本实验的绝对值可能与生产略有差异。但**不影响方差=0的结论**(3次都没传prev_context)。

2. **temperature=0.0的局限性**: 虽然消除了方差，但greedy decoding可能不是最优的。某些情况下，稍微的温度(0.01-0.05)可能给出更好的分数分布。但这引入了方差，需要权衡。

3. **存档Bias(+1.859)的temperature未知**: 存档分数可能是更早版本的模型/prompt生成的，temperature可能不是0.1。无法确定存档vs新鲜的差异完全是temperature导致的。

4. **Bias=-0.181意味着轻微低估**: 从正偏(+0.904)变为负偏(-0.181)。虽然绝对值更小，但方向反转。WLS校准仍然有用(slope=0.496仍然需要)，但offset不同。

## 五、对外部AI的评审问题

### Q1: temperature=0.0消除了方差——这是否推翻了v8.14审视的Q1结论？
v8.14三方AI一致认为"run-to-run方差0.955 > 改善量0.489"是否决reference scoring的核心依据。现在发现温度=0.0时方差=0。**这个发现是否改变了你对v8.14的评审结论？**

### Q2: v8.14对比不公平——是否需要重新评估？
v8.14的"新鲜绝对"用temp=0.1，"参考"用temp=0.0。改善量0.489部分来自温度差异。**如果在相同温度下对比(都用0.0)，reference评分是否还有改善？** (注意：temp=0.0的absolute Bias=-0.181，temp=0.0的reference Bias=+0.415，reference反而更差)

### Q3: 生产环境应统一用什么温度？
- temp=0.0: 方差=0, Bias=-0.181, r=0.494 (最佳)
- temp=0.1: 方差大, Bias=+0.904, r=0.381
**是否应该将llm_score_rubric默认温度改为0.0？** 有什么风险？

### Q4: WLS校准是否仍然需要？
temp=0.0时Bias=-0.181(接近零)。但WLS的slope=0.496仍然说明LLM压缩了分数范围(1分差距→0.5分差距)。**offset校正需求降低了，但slope校正是否仍然必要？**

### Q5: 存档Bias(+1.859)的来源
存档分数的temperature未知。如果存档也是temp=0.0但用的是不同版本的模型/prompt，那Bias差异(+1.859 vs -0.181=2.04)就不是温度造成的，而是模型/prompt版本差异。**如何确定存档分数的生成条件？**
