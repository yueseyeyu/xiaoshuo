⚠ 重大发现：Bootstrap 基线数据源验证失败

通过逐章交叉验证 47 章 golden 数据，确认 Bootstrap 基线所用的 LLM 评分数据精确匹配 v8.14 的 fresh_abs 数据（temperature=0.1 + prev_context），而非 v8.15 标榜的 temperature=0.0 数据。

这意味着本轮 Bootstrap CI 和 k-fold CV 全部基于旧版 temp=0.1 数据计算，v8.15 核心修复（temperature=0.0 消除 run-to-run 方差）并未实际应用到统计分析中。

一、数据源交叉验证

1.1 验证方法

将 v8.14_reference_scoring_data.json 中的 fresh_abs 分数（temp=0.1 + prev_context）和 v8.15_run_to_run_variance.json 中的 LLM 分数（temp=0.0, 无 prev_context）分别与 Bootstrap 基线指标对比，判断哪一数据源与 Bootstrap 结果一致。

根因分析

OLS 校准文件 (ols_calibration_v815.json) 中的 source 字段标注为 "v8.14_reference_scoring_data.json (fresh_abs scores, temp=0.0+prev_context)"，但 v8.14 的 fresh_abs 数据实际是在 temperature=0.1 条件下生成的（生产代码默认值）。该标注存在错误：将 temp=0.1 数据标记为 temp=0.0。

v8.15 的 run-to-run 方差实验 (v815_run_to_run_variance.py) 确实在 temp=0.0 下运行，但该实验 未传入 prev_context 参数（脚本第 125 行：llm_score_rubric(text, ch_num, temperature=0.0)），与生产环境（传入 prev_context）的运行条件不同。

因此存在三种不同的实验条件，但 Bootstrap 只使用了其中第一种：

v8.14 fresh_abs 0.1 Yes +0.904 ✔ (实际使用)
v8.15 variance 0.0 No -0.181 ✖
生产环境 (目标) 0.0 Yes ? 未测试

二、逐题回答

Q1: Bias 的统计显著性

用户问题：Baseline Bias=+0.904, 95% CI [+0.245, +1.585]。CI 不含 0。这个 Bias 是真实的吗？OLS 校准后 Bias≈0，CI=[-0.003, +0.003]。OLS 校准是否有效消除了真实 Bias？

回答

CRITICAL Bias 的统计显著性结论在 temp=0.1 条件下成立，但不能推广到 temp=0.0 条件。

验证结果明确显示，Bootstrap 基线的 Bias=+0.904 来自 temp=0.1 数据。当切换到 temp=0.0 时，Bias 变为 -0.181（方向反转）。这不是误差范围内的波动，而是符号翻转：

条件 Bias_I 方向 95% CI 是否含 0?
temp=0.1 (Bootstrap 实际使用) +0.904 正偏差（高估） 不含 0 显著
temp=0.0 (v8.15 目标) -0.181 负偏差（低估） 需重新计算

temp=0.1 的 positivity bias（LLM 倾向给高分）在 LLM-as-a-Judge 文献中有充分记录。Kostic et al. (2024) 发现 GPT-4 评分存在显著的宽松偏差（leniency bias），对高质量内容尤为明显 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)。RLHF 训练使模型倾向于"帮助性"，在评分场景中表现为系统性地高估。这一 bias 在 temp=0.1 下被放大，因为温度越高，模型越容易生成偏离中性的高分响应。

temp=0.0 的负偏差（-0.181）则可能是另一种机制：greedy decoding 使模型更保守地选择评分量表中间值，导致整体偏低。这在 Engelhard (1992) 的大规模写作评估研究中已有记录——约 80% 的评分落在中间两个类别，形成"分数压缩"（score compression）[$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)。

OLS 校准的有效性：在 temp=0.1 数据上，OLS 确实将 Bias 从 +0.904 消除到 ≈0，CI=[-0.003, +0.003]。这是数学上的必然结果——OLS 回归的残差均值恒等于 0。但这个校准参数（intercept=3.062, slope=0.379）是针对 temp=0.1 数据拟合的，不能直接应用于 temp=0.0 数据。如果将此参数应用于 temp=0.0 的分数，校准后的 Bias 不会为 0。

结论： temp=0.1 Bias 显著但不能推广 需用 temp=0.0 数据重新计算 Bootstrap CI
Q2: OLS 过拟合程度

用户问题：In-sample MAE=1.560, CV MAE=1.603, delta=+0.043。这个过拟合程度是否可接受？考虑到 N=47 偏小，5-fold CV 的 test set 只有 9-10 章。

回答

CONDITIONAL delta=+0.043 本身表明过拟合轻微，但此结论建立在错误数据源之上，需重新验证。

从纯统计角度看，in-sample MAE=1.560 vs out-of-sample MAE=1.603，差距仅 +0.043（2.8%），远低于机器学习中常见的过拟合阈值（>20%）。OLS 只有两个自由参数（intercept + slope），模型复杂度极低，过拟合风险天然较小。这个 delta 是可接受的。

但必须注意两个问题：

  • 数据源错误：上述 CV 结果全部基于 temp=0.1 数据。temp=0.0 数据的 OLS 参数为 intercept=3.108, slope=0.447，与 temp=0.1 差异显著（slope 差 0.068）。temp=0.0 的过拟合程度可能不同。
  • test set 太小：5-fold CV 的 test set 仅 9-10 章。Kohavi (1995) 在 IJCAI 的经典研究中指出，小 test set 会导致 CV 估计的方差很高，单折结果可能严重偏离真实泛化性能 [$TRAE_REF](https://blog.csdn.net/np_hard/article/details/118518854)。Fold 2 的 r=0.004 几乎为零，正是这种不稳定性的直接体现。

Kohavi (1995) 推荐对 N≤100 的数据集使用 stratified 10-fold CV 而非 5-fold，以在每折中获得更多训练数据（~42 vs ~37 章），同时增加折数以降低平均估计的方差 [$TRAE_REF](https://blog.csdn.net/np_hard/article/details/118518854)。Leave-One-Out CV (LOOCV) 也是一个选项，它使用 46 章训练、1 章测试，虽然每折 test set 更小，但平均了 47 次评估，总体方差可能更可控。

结论： delta 可接受但条件性成立 需用 temp=0.0 数据重新验证
Q3: Bias 的高方差

用户问题：5-fold CV 中 Bias std=0.543（从 +0.948 到 -0.377）。这个高方差是否说明 OLS 校准不稳定？还是只是 N=47 的必然结果？

回答

EXPECTED 高方差主要是 N=47 小样本的必然结果，但也暴露了 OLS 校准的结构性脆弱点。

从统计学角度分析：

Fold test_n Bias_I r_I 说明
1 10 +0.948 0.348 正向偏差最大，与全局一致
2 10 -0.236 0.004 r 近乎为零，异常折
3 9 -0.278 0.193 负偏差
4 9 -0.377 0.358 负偏差最大
5 9 -0.088 0.633 r 最高，Bias 接近 0

Bias std=0.543 的高方差有两个层面原因：

1. 小样本统计必然性：Bias 的标准误为 σ/√n ≈ 1.86/√10 ≈ 0.589。这意味着即使真实 Bias=0，单折的样本 Bias 也会在 ±0.589 范围内波动。观测到的 std=0.543 恰好在理论预期范围内，不超出统计噪声水平。

2. 异质性暴露：Fold 1 的 Bias=+0.948 与全局 Bias=+0.904 几乎一致，而 Fold 4 的 Bias=-0.377 则完全反转。这暗示 golden set 的 47 章可能不是同质的——不同子集的 LLM 评分偏差方向不同。这与 v8.14 评审中发现的"文学性作品 vs 纯动作/升级流作品的评分一致性差异"一致。

3. OLS 校准的适用范围：OLS 假设校准关系在所有数据子集上一致。如果不同书籍的 LLM-Human 映射关系不同（例如，文学性小说的 slope 更陡），全局 OLS 可能在某些子集上过度校正、在另一些子集上校正不足。这正是 Fold 2 (r=0.004) 和 Fold 4 (Bias=-0.377) 出现的原因。

从 LLM-as-a-Judge 文献角度看，Chlapanis et al. (2025) 发现不同评分任务领域的 LLM 偏差方向和程度存在显著差异 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)。单一线性校准模型可能无法覆盖所有子集的偏差模式。

结论： 高方差属小样本必然，但暴露子集异质性
Q4: slope 的统计显著性

用户问题：OLS slope=0.379, 95% CI [0.081, 0.651]。CI 不含 0。slope 校正确实需要吗？如果 slope=1（无压缩），CI 会含 1 吗？

回答

SIGNIFICANT slope 校正是统计学必要的，且与 LLM central tendency bias 文献高度一致。

slope=0.379 的含义：LLM 评分每变化 1 分，人工评分仅变化 0.379 分。这是典型的分数压缩（score compression）现象——LLM 的评分动态范围远小于人工评分。

从 LLM-as-a-Judge 文献来看，这一现象有多重理论支撑：

  • RLHF 副作用：经过人类反馈强化学习的模型倾向于"安全"的中性评分，导致极端分数被拉向中间 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)
  • 训练数据中间化：互联网内容以中等质量为主，模型在概率分布上偏向"中等好"的输出 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)
  • Engelhard (1992) 的发现：大规模评估中约 80% 的评分落在中间两个类别 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)

CI 不含 0 的检验：95% CI [0.081, 0.651] 远离 0，p 值 < 0.05，slope 在统计上显著不为 0。这意味着 LLM 评分与人工评分之间确实存在线性关系，只是关系被压缩了。

CI 不含 1 的检验：95% CI [0.081, 0.651] 的上界 0.651 < 1，因此 CI 也不含 1。这意味着 slope=1（即 LLM 评分无压缩、可直接使用）的假设被拒绝。LLM 评分确实需要 scale 校正，不能直接使用原始分数。

temp=0.0 条件下的 slope：v8.15 temp=0.0 数据的 OLS slope=0.447（CI 未计算但点估计更高）。temp=0.0 的压缩程度略低于 temp=0.1（slope 0.447 vs 0.379），但仍然显著小于 1。slope 校正在两种温度条件下都是必要的。

slope 稳定性：5-fold CV 中 slope 范围 0.302-0.427（range=0.125），比 intercept 的 range=0.828 稳定得多。这表明虽然绝对校准参数会因子集变化而波动，但"压缩"这一核心特征是稳定的。

结论： slope 校正确实需要，CI 不含 0 也不含 1 与 LLM central tendency bias 文献一致

三、关键建议

P0 (必须立即执行)

  • 重新运行 Bootstrap + CV：使用 v8.15_run_to_run_variance.json 中的 temp=0.0 数据（47 章 LLM 分数 + 人工分数）重新计算 Bootstrap CI 和 k-fold CV。这是验证所有统计结论的前提。
  • 测试生产条件：在 temp=0.0 + prev_context 条件下重新评分 47 章 golden，这是生产环境的实际运行条件。当前三种条件中，只有这一种未测试但最重要。

P1 (短期内执行)

  • 切换到 stratified 10-fold CV 或 LOOCV：Kohavi (1995) 推荐对小数据集使用 stratified 10-fold CV 以降低方差 [$TRAE_REF](https://blog.csdn.net/np_hard/article/details/118518854)。LOOCV 也是一个选项（N=47 计算量可接受）。
  • 修正 OLS 文件标注：将 ols_calibration_v815.json 的 source 字段从 "temp=0.0+prev_context" 修正为 "temp=0.1+prev_context (v8.14 fresh_abs)"，避免后续混淆。
  • 按书籍分组 CV：当前 5-fold CV 随机分折，可能导致同一本书的章节同时出现在 train 和 test 中，产生数据泄漏。建议使用 GroupKFold（按书分组），测试跨书籍泛化能力。

P2 (中期改进)

  • 引入第二标注者：至少对 47 章中的 20 章进行双人标注，计算 Cohen's Kappa 或 ICC（Intraclass Correlation）[$TRAE_REF](https://blog.csdn.net/weixin_42305039/article/details/132984241)。单一标注者的 golden set 无法区分"LLM 误差"和"标注者主观偏好"。
  • 扩大 golden set：当前 47 章来自 9 本书，高分段仅 6 章。建议补充至少 20 章高分（human_intensity ≥ 7.0）样本，覆盖更多书籍。
  • 考虑分书籍 OLS：如果不同书籍的 LLM-Human 映射确实不同（Fold 2 r=0.004 暗示这一点），可以考虑按书籍特征分组拟合不同的校准参数，而非全局 OLS。

四、学术背景

LLM Central Tendency Bias（分数压缩）

LLM 评分中的 central tendency bias（集中趋势偏差）是一个跨学科、跨时代的系统性问题。从 1950 年代工业心理学的绩效评估研究到 2020 年代的 LLM-as-a-Judge 范式，这一偏差以不同形式反复出现。

核心发现包括：

  • Engelhard (1992)：大规模写作评估中约 80% 的评分落在中间两个类别 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)
  • Kostic et al. (2024)：GPT-4 评分压缩在 85-90 分区间，而人工分布为 8-37 分 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)
  • Li et al. (2025)：LLM 绝对打分存在 rubric order bias、score ID bias 等新型偏差 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)
  • Chlapanis et al. (2025)："方案+分布锚点"条件在所有模型上产生显著改善，MAE 降幅可达 8 倍 [$TRAE_REF](https://blog.csdn.net/weixin_62371528/article/details/159804789)

本项目 OLS slope=0.379 正是这一压缩现象的定量体现：LLM 1 分的差异仅对应人工 0.379 分的差异，scale 被压缩到约 38%。

Bootstrap CI 与小样本

Efron & Tibshirani (1993) 提出的 Bootstrap 方法通过有放回重采样构建统计量的经验分布，避免了正态分布假设。对于 N=47 的样本量，1000 次 Bootstrap 重采样在方法论上是可行的，但需要注意：

  • Percentile CI 在 N<50 时存在已知的覆盖率不足（undercoverage）问题
  • BCa (Bias-Corrected and accelerated) CI 比 Percentile CI 在小样本下更准确
  • Bootstrap 本质上是"从样本中推断总体"，如果样本本身有偏（如 temp=0.1 vs 0.0），Bootstrap CI 会精确地估计错误参数的置信区间

k-fold CV 与小 test set

Kohavi (1995) 在 IJCAI 的经典研究中系统比较了交叉验证和 Bootstrap 用于准确率估计的性能 [$TRAE_REF](https://blog.csdn.net/np_hard/article/details/118518854)。核心结论：

  • 对于小数据集，stratified 10-fold CV 优于 5-fold CV（更高的训练集利用率 + 更低的估计方差）
  • test set 过小（<20）时，单折估计的方差极高，需要更多折数来平均
  • Bootstrap .632 方法在小样本上的表现介于 10-fold CV 和 LOOCV 之间

本项目 5-fold CV 的 test set 仅 9-10 章，Fold 2 的 r=0.004 正是 Kohavi 警告的小 test set 高方差问题的直接体现。

  2. Kohavi, R. (1995). A Study of Cross-Validation and Bootstrap for Accuracy Estimation and Model Selection. Proceedings of the 14th IJCAI, 1137-1143. 推荐对小数据集使用 stratified 10-fold CV。 [链接]
  3. Engelhard, G. (1992). The measurement of rater accuracy. Journal of Educational Measurement. 发现大规模评估中约 80% 评分落在中间类别。
  4. Kostic et al. (2024). LLM 评分与人工评分的偏差研究。GPT-4 评分压缩在 85-90 分区间，人工分布 8-37 分。 [综述链接]
  5. Li et al. (2025). Scoring Bias in LLM-as-a-Judge. arXiv:2506.22316. 定义 Rubric Order Bias、Score ID Bias 等新型打分偏差。 [综述链接]
  6. Chlapanis et al. (2025). LLM 评分中的分布锚点研究。"方案+锚点"条件 MAE 降幅达 8 倍。 [综述链接]
  7. Myford & Wolfe (2003, 2004). Detecting and Measuring Rater Effects. Many-Facet Rasch Model 检测评分者效应的系统方法。
  8. Aamodt, M. G. (2013). Industrial/Organizational Psychology. Central Tendency Error 的经典定义。
  9. Leckie & Baird (2011). Rater Drift in Educational Assessment. 评分者随时间推移向中间值收缩。
  10. Guerdan et al. (2025). LLM 评分量表粒度与可靠性研究。量表越细，随机性越大。
