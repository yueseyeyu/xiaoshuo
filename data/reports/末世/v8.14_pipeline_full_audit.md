## 维度1: 端到端流程

### 1.1 管线流程图

```
小说txt → extract_chapters() → chapter list
    ↓
节奏分析 → rhythm CSV (hook_density, conflict_density, pleasure_intensity)
    ↓
LLM评分 → llm CSV (llm_intensity, llm_retention, llm_conflict, ...)
    ↓
BT pairwise → llm_intensity_bt列 (0.6*rubric + 0.4*BT)
    ↓
Golden校准 → apply_golden_set_calibration() (median offset + shrinkage)
    ↓
Borda/TOPSIS排名 → final_ranking.csv
```

### 1.2 发现的断裂点

**🔴 P0: 生产校准与报告校准是两套独立系统**

- **生产代码** (`llm_batch_score.py` 第1342-1516行): `apply_golden_set_calibration()` 使用 **median offset + shrinkage (v21)**
  - 公式: `calibrated = raw + 0.6 * median_offset`
  - Smart-skip: |offset| < 0.5 时跳过
  - 在 `batch_book()` 结尾自动调用 (第1074行)

- **报告校准** (`scripts/v811_phase1.py`): 使用 **WLS (加权最小二乘)**
  - 公式: `human = 1.928 + 0.496 * LLM` (intensity)
  - 用141章(47人工+95 GLM)拟合
  - 结果保存在 `wls_calibration_v812.json`

- **问题**: 生产管线跑完后的CSV用的是median offset校准，而所有报告和分析用的是WLS校准。**下游消费者看到的是median offset校准的分数，但报告里讨论的是WLS校准的分数**。

**🟡 P1: BT pairwise评分在CSV写入后修改**

`batch_pairwise_scoring()` (第1050-1070行) 在CSV已保存后重新打开并修改:
1. 先保存原始CSV (第1036-1044行)
2. BT评分后重新打开CSV，添加`llm_intensity_bt`列 (第1056-1067行)
3. Golden校准又重新打开CSV修改 (第1074行)

如果BT评分或Golden校准中途崩溃，CSV可能处于半修改状态。

**🟡 P1: 下游消费者不知道用哪个intensity列**

CSV可能有3个intensity列: `llm_intensity`(校准后), `llm_intensity_bt`(BT融合), 原始值被覆盖。`commercial_engine.py`和`borda_ranker`用哪个？

## 维度6: 校准逻辑

### 6.1 生产校准代码分析

**文件**: `src/xiaoshuo/pipeline/llm_batch_score.py` 第1342-1516行

```python
# v21方案: median offset + shrinkage
calibrated = raw + SHRINKAGE * median_offset
# SHRINKAGE = 0.6 (n>=20) 或 0.4 (n<20)
# smart-skip: |offset| < 0.5 时跳过
```

**问题**:
1. **死代码**: `_build_quantile_map()` 和 `_apply_quantile_map()` (第1432-1460行) 被定义但未使用。v20的分位数映射代码被v21的median offset替代，但函数仍保留。
2. **覆盖原始值**: 校准后直接修改 `llm_intensity` 列，原始LLM分数丢失。应该新增 `llm_intensity_calibrated` 列。
3. **与WLS脱节**: 这个校准方法与报告中讨论的WLS完全不同。

### 6.2 WLS校准（仅脚本中）

**文件**: `scripts/v811_phase1.py` (837行)

WLS用141章(47人工+95 GLM)拟合: `human = 1.928 + 0.496 * LLM`

**问题**: WLS只在脚本中运行，结果保存在JSON中。生产管线 `batch_book()` 调用的是 `apply_golden_set_calibration()`(median offset)，不是WLS。

### 6.3 三套校准方案并存

| 方案 | 代码位置 | 公式 | 使用场景 |
|------|---------|------|---------|
| median offset + shrinkage (v21) | llm_batch_score.py | `raw + 0.6 * median_offset` | 生产管线自动调用 |
| WLS (v8.12) | scripts/v811_phase1.py | `1.928 + 0.496 * LLM` | 仅报告分析 |
| Bias-Corrected (v8.14) | scripts/v814_hybrid_analysis.py | `raw - 0.489` | 仅实验，已废弃 |

**结论**: 生产用最简单的median offset，但报告中讨论的是WLS。需要统一。
